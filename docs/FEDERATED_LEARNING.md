# Федеративное обучение AMRI

## Цель

Копии AMRI на разных ПК могут делиться полезным опытом, чтобы новый клиент быстрее получал хорошие стартовые веса и общие знания о качестве типов маршрутов.

Это не синхронизация истории браузера и не отправка локальной базы данных.

## Что разрешено передавать

Только агрегированные и обезличенные данные:

- класс трафика: Web / Video / Realtime / Gaming / Download / Background;
- грубый регион выхода VPN, например NL/DE/FI;
- семейство протокола;
- округлённые значения latency/jitter/loss/throughput;
- агрегированная стабильность и успешность;
- небольшие изменения весов модели AMRI;
- количество локальных измерений, вошедших в агрегат.

## Что нельзя передавать

Никогда не включать в federated payload:

- полный URL;
- домен произвольного сайта пользователя;
- историю посещений;
- поисковые запросы;
- имя процесса или путь к программе;
- локальный IP;
- внешний IP пользователя;
- MAC-адрес;
- SSID Wi‑Fi;
- имя компьютера;
- Windows SID;
- постоянный device ID;
- логин пользователя;
- subscription URL;
- UUID/пароли/ключи VPN;
- содержимое трафика;
- cookies/tokens;
- точную геолокацию пользователя.

## Privacy-by-default

Обмен коллективным опытом выключен по умолчанию.

Пользователь включает его отдельным toggle:

`Обмен обезличенным опытом AMRI`.

Отключение должно немедленно прекращать отправку новых batch-пакетов.

## Передача только через VPN

Даже если payload обезличен, обычный сервер при прямом соединении технически видит публичный IP источника. Поэтому AMRI по умолчанию запрещает отправку federated batch через DIRECT.

Коллективный опыт отправляется только через активный VPN-туннель. В результате AMRI backend видит адрес VPN-выхода, а не прямой адрес провайдера пользователя.

Если защищённый маршрут недоступен, batch не отправляется и остаётся ждать следующей безопасной возможности. Это обучение не должно ухудшать основную работу VPN и не является критическим трафиком.

## Ограничение объёма

Нельзя отправлять каждое измерение отдельно.

Клиент сначала накапливает локальные данные и формирует агрегат только после минимального порога. Начальное значение: минимум 20 измерений.

Один batch ограничен по количеству записей и отправляется редко, а не постоянно.

## Защита от доминирования одного клиента

Model delta обязательно ограничивается по величине. Один ПК не должен иметь возможность резко изменить общую модель.

При агрегации batch-пакеты имеют одинаковый базовый вес: большое количество локальных измерений одного пользователя не даёт ему автоматически больше влияния на глобальную модель.

Глобальное обновление не публикуется, пока не собрано минимальное число batch-пакетов от множества клиентов. После серверной агрегации обновление применяется постепенно.

## Сервер коллективного обучения

В production предполагается собственный AMRI backend, а не сторонний AI-сервис.

Сервер должен:

- принимать только schema-валидные обезличенные batch-пакеты;
- не требовать постоянный device ID для обучения;
- агрегировать данные множества клиентов;
- отбрасывать выбросы и подозрительные обновления;
- публиковать подписанную версию общей модели;
- хранить минимально необходимый срок необработанные batch-пакеты;
- после агрегации удалять сырые batch-пакеты по политике retention;
- не использовать данные для рекламного профилирования;
- не вести журналы исходных IP для federated endpoints, кроме минимально необходимой краткоживущей защиты от атак;
- не связывать federated batch с учётной записью пользователя.

## Что получает другой ПК

Другой клиент получает не чужую историю, а общую модель:

- стартовые веса RouteScore;
- общие поправки для типов трафика;
- агрегированные знания уровня `регион выхода × протокол × класс трафика`;
- версию модели и подпись.

Локальные измерения всегда имеют приоритет над общей моделью, потому что конкретный провайдер и маршрут пользователя могут отличаться.

## Приоритет знаний

Рекомендуемый порядок:

1. Явное правило пользователя.
2. Свежие локальные измерения этого ПК.
3. Локальная история этого ПК.
4. Общая federated-модель.
5. Базовые заводские веса AMRI.

Таким образом коллективное обучение помогает быстрее стартовать, но не заставляет программу слепо повторять решение других пользователей.


## Route Proof

Route Proof остаётся только локально. Destination token, proof hash, previous hash, reason и HMAC-ключ запрещены в federated batch. Коллективный backend не должен уметь связывать квитанции разных устройств.
