# UI Design System

## Цель

Интерфейс должен выглядеть как современное премиальное Windows-приложение, а не как техническая панель VPN.

## Основные принципы

- Скруглённые карточки, окна, поля ввода и кнопки.
- Минимум визуального шума.
- Крупные, понятные элементы управления.
- Современные toggle-переключатели вместо чекбоксов там, где это уместно.
- Плавные состояния hover/pressed/disabled/loading.
- Светлая и тёмная темы.
- Единые отступы и радиусы.
- Аккуратные тени и полупрозрачные поверхности только там, где они помогают иерархии.
- Все важные действия доступны с главного экрана без перехода в экспертные настройки.

## Визуальные токены

- Базовый радиус карточек: 18 px.
- Крупные панели/модальные окна: 24 px.
- Кнопки: 14–18 px.
- Поля ввода: 14 px.
- Toggle: вытянутый pill-контрол с плавным перемещением бегунка.
- Базовый шаг отступов: 4 px; основные значения 8/12/16/24/32 px.
- Минимальная высота основной кнопки: 44 px.
- Главная кнопка подключения: 56–64 px.

## Главный экран

Главный экран должен показывать:

- большой статус `Защита включена / выключена`;
- одну главную кнопку включения;
- режим маршрутизации `Smart / Speed / Ping / Privacy / Streaming / Gaming / Manual`;
- количество активных маршрутов;
- текущий ping, jitter и ориентировочную скорость;
- компактный список активных назначений: приложение/сайт → выбранный маршрут;
- состояние локального AMRI-движка;
- предупреждения только при реальной проблеме.

## Карточка маршрута

Каждая карточка маршрута должна иметь:

- страну/регион;
- название узла;
- источник подписки;
- latency;
- jitter;
- packet loss;
- throughput;
- итоговый RouteScore;
- Confidence;
- состояние `Active / Ready / Probe / Quarantine / Offline`.

## Экран подписок

- Кнопка `Добавить подписку`.
- Поддержка нескольких подписок одновременно.
- Карточка каждой подписки с количеством узлов, числом рабочих узлов, датой последнего обновления и состоянием.
- Toggle `Использовать`.
- Настройка приоритета `Preferred / Normal / Backup`.
- Удаление и ручное обновление.
- Все узлы объединяются в общий пул независимо от источника.

## Экран Smart Routing

Показывать в реальном времени:

`Приложение / домен → выбранный узел → причина выбора`.

По нажатию `Почему?` открывать понятное объяснение:

- текущий RouteScore;
- сравнение с ближайшими альтернативами;
- главные факторы решения;
- confidence;
- была ли смена маршрута и почему.

## Переключатели

Toggle-компонент используется для:

- Smart Routing;
- Kill Switch;
- Auto Update subscriptions;
- Background probing;
- Learning;
- DNS protection;
- Auto failover;
- Startup with Windows;
- Notifications;
- Privacy logging.

## Анимации

Анимации должны быть короткими и функциональными:

- 120–180 ms для hover/pressed;
- 180–240 ms для toggle;
- 200–300 ms для раскрытия карточек;
- плавное изменение RouteScore и сетевых показателей без резких скачков интерфейса.

Не использовать тяжёлые декоративные анимации, мешающие работе.

## Экспертный режим

Экспертные настройки скрываются за отдельным переключателем `Экспертный режим`.

Обычный пользователь не должен видеть десятки технических параметров на главном экране.

## Ограничение проекта

Визуальная система должна быть реализована собственными компонентами приложения. Внешний AI/облачный сервис не участвует в принятии UI или сетевых решений.


## Android

Android использует ту же визуальную иерархию: крупный статус защиты, одна главная кнопка, горизонтальный выбор режима, скруглённые карточки и pill/toggle-переключатели. Платформенный UI не должен заявлять «защита включена», пока transport adapter и packet forwarding фактически не готовы.


## Проверяемый режим экрана «Почему?»

После подключения Route Proof экран показывает статус целостности локальной квитанции решения. Пользователь видит выбранный маршрут, нормализованные факторы, альтернативы и результат проверки цепочки. Raw URL и process name в квитанции не записываются. При повреждённой цепочке UI не скрывает ошибку и не использует такую запись для обучения.


## Языки и направление текста

Windows показывает выбор языка в постоянной навигации и обновляет строки сразу. Android следует системному языку. Поддерживаются девять initial locales: en, ru, es, pt, fr, de, zh-Hans, hi, ar. Арабский интерфейс использует системный RTL layout. Компоненты не должны полагаться на фиксированную ширину английской или русской строки.
