# AMRI VPN — визуальное редактирование исходника

Этот документ предназначен **для разработчика AMRI**. Визуальный редактор находится в исходном
репозитории и **не включается** ни в Windows Setup, ни в Android APK. У пользователей приложения нет
кнопки или режима изменения интерфейса.

## Что редактируется без изменения логики VPN

Главный источник общих визуальных параметров:

`design/amri-ui-theme.json`

Из него генератор создаёт платформенные константы для Windows и Android. Через эти параметры можно
безопасно менять:

- цвета фона, карточек, акцента и текста;
- скругления карточек и кнопок;
- размер кнопки подключения и маленьких иконок;
- внутренние отступы карточек;
- расстояния между блоками;
- отступы экрана сверху, снизу и по бокам;
- общую плотность интерфейса.

Такой подход не затрагивает маршрутизацию, TUN, credentials, DNS, readiness и protection lifecycle.

## Локальный AMRI UI Studio

В репозитории есть developer-only редактор:

`tools/amri-ui-studio/index.html`

Запуск из корня репозитория:

```powershell
python -m http.server 8080
```

После этого открыть в браузере:

`http://localhost:8080/tools/amri-ui-studio/`

Редактор работает локально. Он не нужен и не копируется в пользовательский установщик.

В UI Studio можно переключать предпросмотр **Телефон / Windows**, двигать интерфейс безопасными
отступами, менять размеры и скругления и экспортировать итоговый JSON.

### Как сделать квадрат круглым

Для элемента размером 46×46 круг получается при radius примерно 23 или больше. В UI Studio достаточно
увеличить соответствующее скругление. Для более крупных кнопок действует то же правило: радиус около
половины размера превращает квадрат/прямоугольник с равными сторонами в круг.

### Как «подвинуть» блоки

В responsive-интерфейсе положение задаётся не абсолютными X/Y, а отступами и расстояниями:

- `screen_horizontal` — весь интерфейс левее/правее относительно краёв;
- `screen_top`, `screen_bottom` — вертикальные поля;
- `section_gap` — расстояние между крупными блоками;
- `card_padding`, `hero_padding` — положение содержимого внутри карточек;
- `item_x`, `item_y` — расстояния между соседними элементами;
- `button_x`, `button_y` — внутренние поля кнопок.

Это специально сохраняет нормальную работу на телефонах разной ширины, Windows-окнах, длинных
переводах и арабском RTL.

## Сохранение изменений из UI Studio

1. Нажать **Скачать JSON**.
2. Полученный `amri-ui-theme.json` положить вместо:

   `design/amri-ui-theme.json`

3. Из корня репозитория выполнить:

```powershell
python scripts/generate_ui_theme.py
python scripts/generate_ui_theme.py --check
```

Вторая команда должна завершиться без сообщения `generated file is stale`.

Не редактируйте вручную `apps/windows/src/theme_generated.rs` и
`apps/android/app/src/main/java/ru/amri/vpn/GeneratedAmriTheme.kt`: они перегенерируются из общего JSON.

## Полностью свободный drag-and-drop

Для свободного прототипирования расположения — буквально взять блок мышью и перенести — удобнее
использовать **Penpot** (open-source) или Figma. Это макетный этап, а не код приложения.

Рекомендуемый процесс:

1. Сделать нужную композицию экранов в Penpot/Figma.
2. Сохранить размеры, интервалы, радиусы и визуальную иерархию.
3. Значения, которые уже поддерживает AMRI UI Studio, перенести в `amri-ui-theme.json`.
4. Если меняется сама иерархия блоков (например, карточка серверов должна оказаться выше кнопки
   подключения), один раз изменить структуру исходника:
   - Windows: `apps/windows/src/main.rs`;
   - Android: `apps/android/app/src/main/java/ru/amri/vpn/MainActivity.kt`.
5. После изменения проверить обе платформы и все 9 языков.

Автоматически переносить абсолютные координаты из макета в runtime не рекомендуется: такой экран
будет выглядеть правильно только в одном разрешении.

## Утверждённые изображения и иконки

Канонические изображения находятся в:

`assets/brand/`

Их точные байты защищает `asset-blobs.lock`. Это предотвращает ситуацию, когда сборка незаметно
подменяет утверждённую владельцем картинку другой.

Если вы **осознанно** меняете изображение/иконку, после замены надо намеренно обновить соответствующий
asset lock и проверить ссылки обеих платформ. Не отключайте проверку просто ради прохождения CI.

## Проверка после визуальных изменений

Минимум:

```powershell
python scripts/verify_visual_assets.py
python scripts/generate_ui_theme.py --check
cargo fmt --all -- --check
cargo test --workspace
cargo check --workspace
```

Для Android дополнительно нужен Gradle/Android SDK/NDK. Самый воспроизводимый вариант — отправить
изменения в GitHub и дождаться полного CI, который собирает Rust JNI и APK для arm64-v8a/x86_64.

## Сборка Windows для проверки

```powershell
cargo build --release -p amri-windows
```

Это создаёт приложение, но не полный пользовательский Setup. Полный Setup дополнительно комплектует
проверенные sing-box и Wintun и собирается workflow `Build installable packages`.

## Сборка Android для проверки

Финальный APK AMRI использует проверенные transport binaries по ABI и Rust JNI. Поэтому для релизной
проверки используйте workflow `Build installable packages` или тот же набор release-скриптов/пинов,
что указан в `.github/workflows/installers.yml`.

Не копируйте случайный `sing-box` в APK вручную: release workflow проверяет официальные архивы по
зафиксированным SHA-256.

## Перед выпуском релиза после правок

Порядок:

1. Сохранить визуальный исходник.
2. Перегенерировать Windows/Android theme constants.
3. Проверить asset lock и generated-theme drift.
4. Запустить полный CI.
5. Собрать два installable artifacts.
6. Проверить, что Windows Setup содержит правильные `sing-box.exe` и `wintun.dll`.
7. Проверить, что APK содержит Rust JNI и transport для `arm64-v8a` и `x86_64`.
8. Только после зелёных проверок создавать тег/релиз.

## Что пользователь приложения НЕ получает

Пользовательский Windows Setup и Android APK не содержат AMRI UI Studio, исходный JSON темы,
генератор темы, Penpot/Figma-макеты или developer guide. Эти файлы остаются частью исходной среды
разработки.

Важно: если сам GitHub-репозиторий публичный, другие люди технически могут видеть исходники и этот
редактор. Чтобы доступ к исходному редактору был буквально только у владельца/разработчиков, исходный
репозиторий или отдельный development-репозиторий должен быть приватным. Это не влияет на то, что
в собранных приложениях редактора нет.
